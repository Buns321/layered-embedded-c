# 规范审查清单

本清单是审查路由，不是规则来源。冲突时以 `AGENTS.md` 和 `doc/` 中的原始契约为准。
审查新增代码和本次触碰的旧代码；全仓历史债务另行审计。

## 1. 变更范围与 Git 卫生

- 目标差异只包含当前任务相关文件，没有顺手重构、调试输出、临时文件和生成物。
- 没有覆盖或回退用户未授权的改动。
- 已检查 `git diff --check`。
- 提交信息符合 `type(scope): 简述`，使用简洁祈使语义，并准确覆盖范围。
- 不在同一提交中混入无关格式化、CubeMX 生成噪音或第三方源码变更。

### 1.1 文档变更与人工审批

- `AGENTS.md`、项目 skill、`doc/architecture.md`、`doc/conventions.md`、
  `doc/platform.md`、`doc/platform-contract.md`、`doc/units.md`、`doc/imu.md`、
  `doc/telemetry.md`、板级接口与硬件规范属于受保护文档。
- 任何文档中新增、删除、放宽或重定义约束、约定、架构、接口、单位、所有权、安全或
  硬件规则的变更同样受保护，不受文件路径限制。
- 受保护文档变更必须具有当前会话中的明确人工审批，审批必须指出文件、章节或语义
  范围。普通功能实现请求不构成审批。
- 缺少审批的直接结论是“审查不通过”，不得继续执行 Git 操作，也不得擅自还原文档。
- 普通注释和非规范性小文档可以免审批修改，但仍须通过中文、Doxygen、路径、链接、
  一致性和测试矩阵审查。
- 注释修改若改变单位、范围、所有权、调用上下文、失败行为、并发限制或前置条件，
  按受保护文档变更处理。
- 小文档修改不得与其他规范性变更捆绑，也不得通过“只是改文档”绕过审查。

## 2. 分层与依赖方向

- 依赖只能从 `App/`、`RTOS/` 向上层业务和算法，再向设备、`Platform/` 和 HAL 流动。
- 上层依赖 base 接口，不包含具体驱动、HAL handle 或 MCU 条件编译。
- `Controller/`、`Policy/`、`Filter/` 不反向依赖 `DeviceDrivers/`、`RTOS/` 或 `App/`。
- `System/` 保持运行时服务职责，不承载具体设备策略。
- `Platform/Src/common/` 不包含 HAL 类型；F1/F4 backend 只保留映射、HAL 调用和能力差异。
- HAL 类型只出现在 `Platform/Src/` 和文档明确允许的 CubeMX/System 边界内。

## 3. Platform 公共契约

- 公共头仅包含不依赖 HAL 的枚举、数据、回调和声明。
- F1/F4 对相同公共输入返回相同的 `platform_status_t` 和通用错误位。
- 公共参数错误返回 `PLATFORM_STATUS_INVALID_ARGUMENT`，不依赖 `assert`。
- `assert` 只用于内部不变量和不可达分支。
- 查询接口有明确失败语义，不用合法值表示失败。
- 回调注册返回状态；重复注册返回 busy；一个物理实例只有一个回调所有者。
- 阻塞超时单位为毫秒，超时与 busy 不混用。
- IT/DMA 状态遵循 idle、busy、completion、error、abort 生命周期。
- 异步缓冲区从启动成功到最终事件前保持有效，完成或错误后由上层显式重新启动。
- 未启用实例由 `platform_config.h` 和 CMake 排除；不伪造芯片不存在的能力。
- CubeMX/Core 独占引脚、时钟、DMA、NVIC 和 `MX_*_Init()`；Platform 不重复初始化。

## 4. C 对象模型与所有权

- 具体类型首成员是对应 `*_base_t`，不得复制 base 对象造成切片。
- 具体 `Init` 绑定静态 `*_ops_t`，并初始化全部状态。
- 长期存活软件对象使用 `<role>_h` 命名；按职责命名，不使用 `this`、`self` 或 `obj`
  作为公共接口和回调参数。
- base 视图是非 owning 指针，生命周期和并发所有权在接口注释中写明。
- 静态容器有容量和数量校验，不使用动态扩容。
- 不新增 `malloc`、`calloc`、`realloc`、`free` 或生命周期不明的堆对象。

## 5. 命名与类型

- 公共函数遵循 `Layer_Module_Qualifier_VerbObject`，动作使用不可再拆分的驼峰词。
- 公共 typedef 使用小写蛇形并以 `_t` 结尾。
- 公共聚合类型必须有标签：struct `_s`、enum `_e`、union `_u`，且标签词干与
  typedef 词干一致。
- 公共头不使用匿名 struct、enum 或 union。
- 枚举值和宏使用全大写蛇形；字段、参数和局部变量使用小写蛇形。
- 模块前缀和词序一致：`Platform_*`、`Dev_*`、`Ctrl_*`、`Policy_*`、`Chassis_*`、
  `Filter_*`、`Sys_*`、`Sys_Log_*`、`RTOS_*`。
- 通用项目 API 统一使用 `UART`，不再引入新的 `USART` 混合命名。
- CubeMX/HAL 生成符号可以保留原名，项目包装层不得沿用其命名风格。

## 6. 中文注释与 Doxygen

- 项目维护的每个 `.c/.h` 都有 Doxygen 文件头，包含 `@file`、中文 `@brief` 和分组。
- 公共头使用 `@addtogroup` 并在末尾以 `/** @} */` 关闭。
- 实现文件和私有头使用 `@ingroup`。
- 新增分组写入 `doc/doxygen/groups.dox`。
- 新增维护中的文档、公共头或测试目录同步进入 `Doxyfile` 的 `INPUT`。
- 项目自有注释、文档和 Doxygen 描述使用简体中文；标识符、协议名和芯片术语保留原文。
- 不保留整句英文说明。
- 所有函数注释不得只有 `@brief`；每个参数写明 `@param`，非 `void` 返回写明
  `@return` 或逐状态 `@retval`，并按实际契约用 `@pre`、`@post`、`@note` 或
  `@warning` 说明前置条件、后置状态、副作用、单位、范围、所有权、调用上下文、
  失败行为或并发限制；无参数且返回 `void` 的函数也至少说明 `@post` 或 `@note`。
- 公共头声明与 `.c` 定义各有一份同步的契约注释；私有函数前向声明和定义两处
  说明同步。
- 注释说明单位、范围、所有权、调用上下文、失败行为和并发限制，不复述代码。
- `//` 只解释实现原因、状态机步骤或数据手册约束。
- 任何维护中的 `.c/.h` 或 `Doxyfile` 输入文档发生变化后重新生成 Doxygen，警告必须为零。

## 7. 单位、时间与数值边界

- 对外使用 SI 单位：m、s、rad、m/s、rad/s；IMU 姿态使用 deg，角速度使用 deg/s。
- `dt_s` 单位为秒且有限、大于零；`time_ms` 单位为毫秒。
- 新增或修改的物理量参数、字段、局部变量、全局变量、常量和宏以
  `doc/units.md` 登记的规范单位后缀结尾；存量不合规标识符不得借无关改动
  继续扩散。
- 电机目标与反馈为 m/s，控制律输出和 `max_duty` 为 duty，编码器为 counts。
- PWM 使用 `ccr = ARR * duty / max_duty`，实现避免中间乘法溢出。
- SPI 16 位模式长度为偶数且地址对齐；ADC/DMA 长度语义是转换次数。
- 对外部输入检查有限值和范围；非有限值按契约清零或返回错误。
- 编码器 `get_delta` 每周期只消费一次。

## 8. 初始化、状态与错误

- `Init` 先校验指针、数量、枚举、范围和关键常数。
- 可失败初始化返回状态，调用方检查结果，不静默忽略。
- 运行期错误使用状态枚举；`assert` 不承担外部输入校验。
- 错误快照在公共操作开始时清理，只在只读查询中返回。
- 状态切换和失败后的恢复路径有明确契约，不留下部分初始化对象。
- 数值和输出在跨越模块边界前完成有限性检查。

## 9. ISR、RTOS 与并发

- ISR 只做清标志、最小搬运、入队和重新挂接，不解析复杂协议、控制或格式化浮点。
- ISR 不阻塞、不分配内存、不等待锁。
- ISR 与任务共享变量使用 `volatile`，并明确单写者/单读者关系。
- 共享快照和复合状态使用 System 临界区或 RTOS 原语保护。
- 复杂计算和滤波在临界区外执行。
- 任务周期、控制周期常数和真实调度周期保持一致。
- 不把遥测格式化、DMA 等待或高频日志放入实时控制任务。

## 10. 模块专项契约

### IMU 与滤波器

- 具体 IMU 只采集、换算、标定并提交本次更新的原始通道。
- `imu_base_t` 负责注册滤波器、合并异步帧、保存 raw/filtered 快照和逐通道时间。
- WHT101 只发布 yaw 和 gyro-Z；MPU6050 首版发布 accel/gyro 六通道。
- 不支持的通道不进入 `valid_mask`；滤波输出沿用输入 `time_ms`。
- 上层只读取滤波后的 `imu_sample_t`，不解释具体寄存器。
- `GetSample()` 等跨任务读取使用一致快照，不在临界区内执行复杂滤波。

### Controller、Policy 与 Chassis

- Controller 是轮级 SISO，输入 target/measure 的当前物理量，输出执行器量；
  新增或修改接口的参数名须带单位后缀，例如 `target_mps`、`measure_mps`。
- Policy 是底盘级 MIMO 解算，不与 Controller 职责混合。
- Chassis 只保存命令、检查 IMU 新鲜度、调用 policy 并向电机写目标。
- 电机闭环由 `motor_base` 运行，Chassis 不重复控制环。
- IMU 无效或过期时保持制动锁存，恢复必须显式重新使能。

### Filter

- `filter_sample_t` 固定容量；通道索引和 `valid_mask` 一致。
- `Filter_Base_Update` 先全量复制输入到输出，再调用具体 filter。
- 不复制输入输出别名，不修改 `time_ms`，不越界使用通道位。
- Chain 和 Distributor 的容量、重复项和输出冲突在初始化阶段拒绝。

### 遥测与日志

- Telemetry `send` 非阻塞，整帧接受或整帧丢弃，忙时暴露 busy 和统计。
- DMA 发送缓冲由具体设备对象持有，完成前不得被下一帧覆盖。
- 普通日志只在任务上下文调用；高频浮点数据使用 JustFloat。
- RTT 原始源码只能由 `system_log_rtt.c` 直接包含。
- 共享 UART 只有一个回调所有者，不与另一个独立回调用户并行接管。

### Board、CubeMX 与硬件

- Board 负责固定引脚语义、设备归属、共享资源和初始化顺序。
- 引脚、复用、时钟、DMA、NVIC 与 `.ioc`、板级文档一致。
- CubeMX 生成文件只在 `USER CODE` 区域修改。
- `Drivers/`、`Middlewares/` 和第三方源码不手改。
- STBY 分组、复位安全电平、共享总线和 DMA 冲突有明确处理。
- 板级改动同步 README、hardware map、验证顺序和资源预算。

## 11. 构建、测试与文档

- 新源文件同步加入正确 CMake 目标；新公共头同步加入 Doxygen `INPUT`。
- 使用 `target_include_directories`，不新增大量 `../../` include。
- `-Wall -Wextra` 无新增警告；测试目标保持 `-Werror`。
- 受影响的 Debug 目标构建通过；共享 Platform 或 System 同时验证 F1/F4。
- 行为变更具备新测试或回归测试，覆盖非法参数和错误路径。
- 测试失败、跳过、缺失或证据不完整时审查失败。
- 文档中的命令、路径、宏、类型名和实际实现一致。

## 12. 审查失败输出

审查失败时必须以醒目阻断语开头，并逐项提供：

- `文件:行` 和失败类别。
- 违反的 `AGENTS.md` 或 `doc/` 条款原文或准确指代。
- 测试命令、退出码和关键日志；没有可执行测试时说明文档或结构检查失败点。
- 具体修复动作和修复后必须重跑的检查。
- 必须重新阅读的精确文档链接和章节。
- 若为受保护文档缺审批：文件、语义范围、缺失的审批语句和停止条件。

必须明确写出：

> **强制动作：修改前必须重新打开并逐条阅读上述文档。禁止凭记忆、猜测或旧结论修复。**

不得只给笼统结论。无法定位到文件或条款时必须说明阻塞原因并停止。

## 13. 审查通过报告

最终报告至少包含：

- 审查范围。
- 发现并修复的违规。
- 执行的测试、构建和文档检查及其结果。
- 未执行的检查、原因和剩余风险。
- 受保护文档变更及对应人工审批，没有则明确“不涉及”。
- 是否允许执行用户请求的 Git 操作。
